    从静态路由迁移到 OSPF 后，BGP ECMP 为什么只剩一条¶

    结论¶

    问题不在 BGP 会话，也不是 OSPF 没有学全路由，而是两个 BGP 下一跳递归后的 IGP cost 不相等。

    SSTP 使用 PPP 点对点地址：RouterOS 本地地址是 192.168.20.1，对端地址是 192.168.20.2。PPP 产生的是对端 192.168.20.2/32 直连路由，因此 OSPF 能自然发布的是对端 /32，不是本地的 .20.1/32。旧的 BGP 导入策略仍把 SSTP 路径下一跳改写成 .20.1，只能依赖遗留的 192.168.20.0/30 静态路由；WG 下一跳则通过 OSPF 递归。两条路径的 IGP cost 因而不同，无法进入同一组 ECMP。

    最终把 SSTP 的 BGP 下一跳改为 PPP 对端 192.168.20.2，删除遗留静态路由，让 SSTP 与 WG 都通过 OSPF 等价递归，ECMP 恢复。

    背景变更¶

    AR 与 RouterOS 之间原先依赖多条静态路由。为了减少配置耦合并便于后续迁移，改为：

    • OSPFv2 Area 0；
    • AR Vlanif1 与 RouterOS br-lan 使用点对点网络类型；
    • 只重分发 192.168.0.0/16 内的直连路由；
    • 清理由 OSPF 已经覆盖的内部静态路由；
    • BGP 继续负责业务前缀，并通过导入策略改写业务下一跳。

    OSPF 邻居建立正常，隧道网段也已经学习成功，但清理静态路由后，原本的双隧道 BGP ECMP 只剩一条生效路径。

    现象¶

    • OSPF 邻居为 Full；
    • SSTP、WG 及其他 BGP 邻居均为 Established，发送队列为空；
    • 同一业务前缀能看到两条 BGP 路径；
    • 只有一条进入转发表，另一条提示 IGP cost 不优；
    • 重启对应 BGP 会话后现象不变。

    这组现象说明控制平面没有断链，问题发生在 BGP 最优路径与多路径资格判断阶段。

    根因¶

    迁移前的递归关系是：

    SSTP BGP 路径 → 192.168.20.1 → 192.168.20.0/30 静态路由
WG   BGP 路径 → 192.168.30.1 → OSPF 路由

    静态路由与 OSPF 路由的代价不同。即使两条 BGP 路径的 Local Preference、AS Path 等属性满足多路径条件，只要下一跳的 IGP 递归代价不相等，设备仍不会把它们安装为等价路径。

    关键误区在于把 SSTP 当成普通以太网 /30。PPP 链路真正有意义的直连可达对象是对端地址：

    RouterOS 本地：192.168.20.1
PPP 对端：     192.168.20.2/32

    因此 .20.2 能由 OSPF 正常传播；.20.1 作为本地接口地址，并不会以同样方式成为对端设备上的 OSPF 可达前缀。

    为什么重启 BGP 没用¶

    重启只能重新建立会话、重新接收路由并重新执行选路。这里的输入条件没有变化：导入策略仍把下一跳写成 .20.1，底层递归路由的 cost 仍然不一致，所以重新计算只会得到相同结果。

    遇到“会话正常但 ECMP 消失”时，应先比较两条候选路径的完整属性和下一跳递归结果，不应把重启当作修复。

    处理方案¶

    先完成变更前配置备份和可执行回滚记录，再进行两项调整：

    route-policy SSTP_IMPORT permit node 10
 apply ip-address next-hop 192.168.20.2

    随后删除只为旧下一跳服务的静态路由：

    undo ip route-static 192.168.20.0 255.255.255.252 192.168.1.2

    最后只重置 SSTP 对应的 BGP 邻居，不影响其他会话。

    调整后的递归关系变为：

    SSTP BGP 路径 → 192.168.20.2/32 → OSPF
WG   BGP 路径 → 192.168.30.1/30 → OSPF

    两条路径的递归代价均为 2，满足 ECMP 条件。

    验证¶

    变更后逐项确认：

    • OSPF 邻居仍为 Full；
    • 四个 BGP 邻居均为 Established，发送队列为 0；
    • 抽样业务前缀显示两条可用路径、两条被选入多路径；
    • 转发表同时出现 SSTP 与 WG 两个 EBGP 下一跳；
    • 连通性测试无丢包；
    • 保存变更后配置，并与变更前配置分别计算 SHA-256。

    回滚原则¶

    回滚顺序必须先恢复下一跳可达性，再恢复旧的 BGP 下一跳策略：

    1. 恢复 192.168.20.0/30 静态路由；
    2. 把 SSTP_IMPORT 下一跳改回 192.168.20.1；
    3. 只重置 SSTP 对应的 BGP 邻居；
    4. 等待会话恢复并检查路由表后再保存。

    完整配置快照只保存在私有备份中，不进入公开知识库。

    可复用经验¶

    1. ECMP 不只比较 BGP 属性：还要检查下一跳的递归协议、路由 preference 与 cost。
    2. PPP 不能按广播网段理解：优先使用系统实际生成的 peer /32 路由作为跨设备下一跳。
    3. 迁移动态路由时要审计递归依赖：删除静态路由前，逐个检查 route-policy、策略路由和隧道探测是否引用旧地址。
    4. 重启协议不是诊断手段：属性或递归条件不变，重启只会重现问题。
    5. 基线与复盘分开：当前架构页记录最终状态，复盘保留为什么这样改以及如何回滚。
