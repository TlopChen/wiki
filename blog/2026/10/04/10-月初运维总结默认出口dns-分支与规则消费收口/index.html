    10 月初运维总结：默认出口、DNS 分支与规则消费收口¶

    本轮对照共享工作区 Markdown、历史证据、广州 Git / Wiki 和四机运行状态，核验于 2026-10-04 22:01–22:03，北京时间。最大的遗漏是默认出口已优先日本，DNS 页面还停在旧入口与缓存模型。这里整理最终状态，保留未解决的边界。

    已落地的变化与改进¶

    范围 最终状态 收益与边界
    规则仓库 脚本 / 输入 / 输出分层，服务器只留数据 来源可追溯，减少代码回灌漂移
    手工规则 广州每分钟监视六个输入，命中才生成发布 上游日更；ROS 立即消费仍需手动
    设备消费 ROS 唯一拉六表 + 三文件，OxiDNS 本地 reload 离线可重载；多表导入不是整体事务
    路由 国内宣告 DIRECT_IP 分表，AR 优先缺省指向日本 ROS 非 DIRECT_IP PCC 承接；全故障场景未验收
    DNS 互斥三段，无应答 SERVFAIL 去掉重复 JP 与跨组回退
    缓存 纯内存、关闭负缓存、lazy=600 秒 其它节点缓存仍存在
    隧道 移动腿换源端口恢复，JP 恢复双腿竞速 源端口不轮换；竞速可靠性仍待查
    清理与文档 旧素材和副本移入备份，Git / Pages 两篇已更新 历史保留，本轮继续校正现状页

    实测与实施记录的区别¶

    广州 Git 为 409899e，Wiki 更新前为 be95748，工作树均干净、与远端 main 一致。相对 10-01 的 7b8d346，新增六次自动日更，变更是上游快照与产物，所查生成器与消费脚本无新增差异。今天本地出现的探查和部署候选文件不能算作生产已实施。

    AR 国内 BGP 收到 7646 / 6909，日本各 2455；ROS DIRECT_IP=6326，分表=7646 / 6909，与广州报告一致。默认 PCC 实时存在；准确实施时间和操作者缺少完整归档，本次只记“现状确认”，不补造过程。

    三隧道对端各三次 ping 无丢包；OxiDNS health / reload 正常，运行版本 0c0ee0a4，国内外 A 成功。广州镜像健康，日本 dnsmasq / WG active，两台 Linux 无 failed unit。采样健康不等于长期稳定。

    尚未解决¶

    • DHCP 仍下发 AR 备用，AR 保留运营商解析器；主链不跨组没有消除这条旁路。本工作机现仅 OxiDNS，不能代表全网。
    • 累计 CN error=182 / timeout=27，JP error=5 / timeout=2；JP 两腿 query=9195，移动 success=30、电信=9158。需要核对竞速取消与报文，不能直接认定移动腿丢包。
    • 优先缺省未配置端到端 NQA，ROS check-gateway 只证明对端可达；两腿全失效、日本公网故障行为未验证。
    • 只从代理源排除某域名，若不在国内表仍走 JP；直连意图需同时核对域名表与数据面。
    • 新 DNS 驱动路由方案目前只有可行性报告，未实现或部署，不计入已完成改进。

    10-02 DNS 判断有后续反证；10-03 失败跨组回退有对应日志和链路证据；10-04 确认 AR 旁路配置存在。不能把不同阶段合并成一个已完全证实的“唯一根因”。
